Evidence-bounded AI agent security evaluation

This page points to open research and tooling relevant to AIUC-1 readiness. It is not a certification, a compliance determination, or an assessment of any third-party deployment.

View the Agent Security Harness View the AIUC-1 standard

How to use this reference

Start with the harness repository, its pinned releases, and the documented test catalog. Reproduce a result from the specified revision before relying on it. The repository, rather than this page, is the source of truth for current code and coverage.

A mapping between a test and a standard requirement is not certification. It describes a bounded relationship that should be independently reviewed for the target system and the relevant version of the standard.

Evidence classes

The harness distinguishes evidence rather than treating every test result as the same kind of proof:

  • E1 - observational: source or configuration inspection.
  • E2 - runtime characterization: a bounded observed behavior in a stated environment.
  • E3 - enforcement: a demonstrated control at the relevant boundary.
  • E4 - persistence and replay: an independently repeatable, recorded result.
  • E5 - isolation: evidence that a control remained effective under the stated isolation conditions.

Scope and limitations

Open-source test tooling can support a readiness review, but it cannot establish that a system is secure, certified, or compliant. Results depend on the target, configuration, test version, authorization, and evidence record. Do not generalize a local or synthetic result to a vendor, customer, or production environment without appropriate authorization and independent validation.
